# KIKO 문서 감사 절차

규칙: `.claude/rules/kiko/evidence-and-eval.md`. 글을 쓴 에이전트가 자기 글을 감사하지 않는다. 가능하면 `doc-auditor` 에이전트에 맡긴다.

## 1. 주장 목록 뽑기

문서에서 검증 가능한 문장을 전부 뽑아 표로 만든다. 한 문장에 주장이 여럿이면 나눈다.

- 수치: 정확도, 비율, 건수, 지연, 표본 수, 날짜
- 구조: "N개 툴", "N개 노드", "~일 때만 발동", "~을 저장하지 않는다"
- 인과: "A 때문에 B를 바꿨다", "도입 후 개선"
- 설정: 모델명, 임계값, TTL, 플래그 on/off

## 2. 주장마다 원천 확인

| 주장 종류 | 확인할 곳 |
|---|---|
| 동작·구조 | `origin/dev` 코드. 로컬 체크아웃이 뒤처졌을 수 있으니 `git fetch` 후 `git show origin/dev:<path>` |
| 설정값 | 배포 env(`docker exec ai-server env`). `config.py` 기본값은 근거가 아니다 |
| 운영 수치 | dev-app DB(`ai.log_conversation_event`, `ai.chat_messages`, `ai.user_taste_profile` 등) 직접 집계 |
| 평가 수치 | 저장소의 평가 스크립트 + 결과 기록(PR 설명, 커밋 메시지). 기록이 없으면 `kiko-eval`로 재측정 |
| 도입 경위·날짜 | `git log -S`, PR 번호, 커밋 메시지 |

## 3. 판정

각 주장에 하나를 붙인다.

- **맞음**: 원천과 일치. 근거 위치(파일:줄, 쿼리, 커밋)를 적는다.
- **틀림**: 원천과 다름. 실제 값과 근거를 적는다.
- **범위 누락**: 수치는 맞지만 조건이 빠짐. 예: 상한값을 성능처럼, 커버리지를 정확도처럼, 자체 제작 평가셋 미표기, 페르소나 단독 평가를 에이전트 전체 평가처럼.
- **충돌**: 기록끼리 값이 다름. 어느 쪽으로도 단정하지 않고 양쪽 출처를 적는다.
- **확인 못 함**: 원천을 찾지 못함. 문서에서 빼거나 보류를 제안한다. 추측으로 채우지 않는다.

## 4. 자주 걸리는 유형 (실제 사례)

- 기본값을 운영값으로 씀: `config.py`의 `nova-lite` vs 운영 `claude-haiku-4-5` (8/23)
- 상한값을 성능으로 씀: 정답 라벨을 타깃으로 넣은 rerank 실험 fit 0.38→0.83 (9/28)
- 커버리지를 정확도로 씀: 무드 태그 98% (9/28)
- 개수 서술 오류: "8번째 툴 제거"는 9→8개 (9/23)
- 평균과 부분 수치 혼동: 라우팅 81%는 전체, 60/50/67은 게이트 미달 유형만 (9/23)
- 서술과 코드 흐름 불일치: "0건이면 evaluator 채점" vs 실제 fast-path, 직전 결과 채점 버그 (9/24, #295)
- "저장하지 않는다", "N일 뒤 삭제" 같은 데이터 보존 주장: DB에서 실제 행으로 확인 (9/28: 원문 대화 저장됨, 비선호는 삭제가 아니라 반감기)

## 5. 산출물

- 판정 표(주장 / 판정 / 실제 / 근거)
- 틀림·범위 누락 항목별 대체 문구 제안
- 확인 못 함 목록
- 문서를 고친 뒤에는 고친 문장만 다시 대조한다.
