1. Product Loop

how it works
  1. 1
    Entry — 사용자가 SMS 또는 Telegram(@no_scroll_bot)으로 첫 메시지.
    전화번호 +1 (415) 305-4858 / +1 (415) 718-4828 모두 동일 백엔드로 라우팅.
  2. 2
    Account link — 봇이 noscroll.com/hi/<token>?platform=telegram 링크 발송 → X OAuth 연동
    X likes / bookmarks / follows 를 임포트해서 취향 시드 생성 (콜드스타트 X)
  3. 3
    Beat setting — 자연어로 "내가 뭘 보고 싶은지 / 뭘 빼야 하는지" 설정
    예: "crypto regulation news, but skip price-only posts"
  4. 4
    Sample → Trial → Paid — 무료 샘플 1회 → 7일 트라이얼 → $9.99/월
  5. 5
    Delivery — 사용자 지정 cadence (주 1 ~ 일 N회) + breaking 발생 시 즉시 인터럽트
  6. 6
    Reply loop — 모든 알림에 자연어 응답으로 dig-in / 조정 → 취향 강화

3. QR 로 Telegram 다이렉트 등록

deep-link · start_param

noscroll 이 쓰는 패턴은 Telegram 공식 start_param 딥링크. QR 은 그 URL 을 단순히 이미지로 인코딩한 것일 뿐 — 핵심은 1회용 토큰 ↔ chat_id 바인딩. 

# 흐름
[웹]                                [사용자]            [Telegram]
1. POST /api/telegram/link-token
   → token = uuid(), TTL 10분
   → Redis: token → web_user_id
                                    ─▶ QR 스캔
                                        https://t.me/kiko_fashion_ai_bot?start=<token>
2.                                        Telegram 앱 자동 오픈
3.                                        "Start" 버튼 노출
4.                                        탭 → 봇이 받는 메시지: "/start <token>"
5. webhook 수신
   chat_id ↔ token ↔ web_user_id 바인딩
   토큰 즉시 폐기
                                    ◀─ "환영해요! 계정 연결 완료 🐱"
A. 웹 → Telegram
  • kikoai/app 에서 토큰 발급 API
  • 프론트에서 qrcode npm 으로 QR 생성
  • 이 AI 서버 app/api/webhooks/telegram.py 에서 /start <token> 패턴 매칭
  • users.telegram_chat_id 업데이트 → 토큰 폐기
B. Telegram → 웹 (반대)
  • 봇이 https://kikoai.com/hi/<token> 발송
  • 웹에서 토큰 검증 → 세션 생성
  • Telegram-first 회원가입 플로우
  • noscroll 의 /hi/<token>?platform=telegram 이 정확히 이 패턴
결제 통합 (추후)
Telegram Stars / Payments 로 in-chat 구독 가능. noscroll 은 외부 결제 사용. $9.99/월 + 7일 트라이얼 모델은 PMF 검증 후 차용 권장.

4. Karpathy 어록 검증 — kiko에 적용할 교훈

5개 중 2개 날짜 오류
# 어록 noscroll 실제 평가
1 "The hottest new programming language is English." 2025-06 2023-01-24 ❌ 2.5년 ↓
2 "claim the leverage from the use of agents..." 2026-02 2026-02 ✅ ✅
3 "fully give in to the vibes..." (vibe coding) 2025-09 2025-02-02 ⚠️ 7개월 ↓
4 "For now, autocomplete is my sweet spot." 2025-10 2025-10-17 ✅ ✅
5 "express my will to my agents for 16 hours a day." 2026-03 2026-03-20 ✅ ✅
★ Insight

noscroll은 출처는 잘 찾지만 timestamp 메타데이터를 LLM에 추론시키는 듯. 팟캐스트(2025-10, 2026-03)처럼 명시적 발행일이 있는 소스는 정확하고, 오래된 트윗은 LLM이 "최근에 한 말 같다"로 envelope를 추론하면서 어긋남.

kiko 적용: 패션 신상 큐레이션할 때 "FW25 신상" / "5월 입고" 같은 시즌·출시일 메타데이터는 product DB의 신뢰 가능한 컬럼에서만 끌어와야 함. LLM이 이미지·이름 보고 추론하게 두면 같은 함정.

5. 우선순위 백로그

P0 → P3
P0 · 즉시 no SPEC needed · ~1 PR

A. 문장 분할 발화 + sendChatAction

app/graphs/nodes/respond.py 출력을 문장 split (".", "!", "?", "\n\n") + 200ms 딜레이. 매 sendMessage 직전 sendChatAction("typing") 1회. 작은 변경으로 대화 톤이 확 살아남.

P1 · 다음 SPEC-START-GUIDE-001 (가칭)

B. /start 개선 + 카드 온보딩

(1) 소개 3줄 + 사용법 3줄 → (2) 카드 온보딩 (무드 8 · 컬러 6 · 핏 4 멀티셀렉트, InlineKeyboardButton) → (3) user_taste_profile 초기 가중치 시드. 기존 SPEC-CLARIFY-CARDS-001 인프라 재활용.

P2 SPEC-PINTEREST-BOOTSTRAP-001 (가칭)

C. Pinterest 보드 부트스트랩

보드 URL 받기 → Apify로 핀 50~100개 크롤 → Vision 일괄 분석 → TasteProfile 강한 시드. 카드 온보딩 대안/병행 경로. IG saved는 비공개 한계로 후순위.

P3 SPEC-SAVED-BRANDS-001 + SPEC-NOTIFY-2TIER-001 (가칭)

D. Brand save + 신상 푸시 (2-tier 알림)

saved_brands 테이블 + 카드에 ❤️ 버튼 + 명시적 저장 액션 (이미 있는 implicit-fb 보강). 신상 매칭 푸시는 product DB 크롤러 자동화 선결 후 발동.

P3+ SPEC-GROUP-CHAT-001 (가칭)

E. Group chat mode

친구 단톡방에 kiko 추가 → 공동 코디 추천. multi-chat_id 라우팅 + per-group TasteProfile. 성장 루프지만 PMF 확인 후 진입.

검증 대기: QR이 ?start=<token> 딥링크인지 확인 (web↔Telegram 계정 바인딩 필요 시). 현재는 봇 진입은 동작 ✅
